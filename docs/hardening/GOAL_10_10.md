# COS GRAPH ENGINE — 10/10 ENGINEERING NORTH STAR

## Mission
Bring COS Graph Engine to a demonstrable 10/10 engineering standard across all critical dimensions before it becomes authoritative infrastructure for AGENTIC_SYSTEMS_OS.

## 10/10 means
A dimension is 10/10 only when its guarantees are:
- explicitly specified;
- falsifiable;
- machine-verifiable;
- deterministic where applicable;
- tested under nominal and failure conditions;
- observable;
- replayable/recoverable where state is involved;
- permission-safe;
- concurrency-safe;
- documented for cold agents;
- reproducible from a clean environment;
- free of suppressed required failures;
- validated with cost-aware local-first execution.

Model confidence, feature count, LOC, test count, README claims, benchmark labels or a green badge alone cannot produce 10/10.

## Hard constraints
- Incremental recurring infrastructure cost: EUR 0/month.
- Local/container verification is default.
- GitHub Actions are manual-only during Convergence Era unless explicitly approved for a release/security/restore gate.
- CD is OFF during Convergence Era.
- Codex is optional, not required; use only when an interactive persistent repo-local loop materially improves execution.
- No new product levels/features until critical assurance gates are closed.

## 20 dimensions and 10/10 exit conditions
1. Vision & architecture — boundaries, authority and invariants are explicit and non-contradictory.
2. Monorepo integrity — clean install/build from fresh checkout; dependency graph consistent.
3. Graph correctness — mutation-safe indexes, multiedges, invariants, deterministic serialization.
4. Algorithms/performance — seeded scientific benchmarks, complexity budgets, regression thresholds.
5. Temporal semantics — bi-temporal truth, supersession, as-of queries, deterministic replay.
6. Event architecture — durable append-only events, ordering/causation/correlation, idempotency.
7. Persistence/recovery — snapshots, replay, restore drills, graph-hash equivalence.
8. GraphRAG/retrieval — provenance, permission filtering, hybrid ranking, gold-query evaluation.
9. Memory — epistemic typing, temporal validity, contradiction/supersession, safe consolidation.
10. Agent runtime — durable plans/runs, leases, acceptance gates, compensation/rollback.
11. Security/policy — deny by default, unknown operators fail closed, scoped retrieval/writes, audit.
12. Concurrency — optimistic concurrency/CAS, leases, idempotent writes, race/failure tests.
13. Resilience — degraded states, near misses, interacting failure modes, fault injection.
14. Observability — traces/metrics/logs tied to runs, queries, projections, policy and failures.
15. Testing — canonical discovery, no orphan suites, mutation/property/failure/security coverage.
16. CI/CD truth — CI fail-closed; no false green; CD disabled until explicit authority gate.
17. Deployment/infra — reproducible, zero-cost compatible, optional deployment paths isolated.
18. Developer/Agent DX — deterministic README_FIRST/AGENTS/HANDOFF, reproducible commands, low ambiguity.
19. Governance — protected truth, small guarantee-oriented PRs, evidence ledger, supersession discipline.
20. Interoperability — stable adapters/contracts for GitHub, Drive, Supabase, ChatGPT/Claude/Gemini/Codex.
